# Telegram 手机控制通道

[English](README.md) | 中文

`@deepseek-ai/dsh-channel-telegram` 可以把一个经过电脑端确认的 Telegram 私聊接入 DeepSeek Harness。它通过通用的 `@deepseek-ai/dsh-channel` 服务提交文字消息，默认关闭。

## 怎么配置

1. 用 [BotFather](https://t.me/BotFather) 创建机器人，把 Token 保存到 Host 的 `TELEGRAM_BOT_TOKEN` 凭据中。Token 不会写进设置、通道存储、日志或远程接口。
2. 在桌面端设置中点击“开始配对”。客户端会先检查机器人身份和 Webhook 状态，然后生成一个 10 分钟有效的 `t.me` 链接。
3. 用手机打开链接，在 Telegram 私聊里发送 `/start <token>`。
4. 回到电脑，核对 Telegram 账号信息并点击“确认”。电脑确认前，手机消息不会被当作任务提交。
5. 点击“停用”只会停止轮询，保留配对状态或已绑定账号；再次启用时会重新检查 Bot Token 和 Webhook。点击“解除绑定”才会停用并清除待确认账号和已绑定账号。“解除绑定”也会清除旧机器人身份和 offset，换 Bot 后会从新 Bot 的更新开始处理。两种操作都不会删除已经保存的 Bot Token。
6. 当本机无法直连 `api.telegram.org` 时，桌面端设置可以保存一个可选的 HTTP(S) 代理地址（例如 `http://127.0.0.1:7890`），只作用于 Bot API 请求。该配置会经过校验（不允许携带用户名密码、路径、查询或片段），保存在通道存储中、随安全状态一起返回，并在“解除绑定”后保留；保存或清空代理会让运行中的轮询器自动重启。留空保存即恢复直连。

## 安全规则

- 只接受一个经过确认的私聊 `(userId, chatId)`，群聊和其他账号都会被忽略。
- 只要发现已有 Webhook，长轮询就不会启动；程序不会自动删除 Webhook，也不会把 Bot API 的 `409` 简单归因成某一种冲突。
- 配对码有 128 位随机强度，只能使用一次，10 分钟过期；磁盘中只保存它的 SHA-256 摘要。
- `getUpdates` 固定只请求 `message`。只有消息已经安全写入 Harness（或确认属于已处理的重复消息）之后，才会推进 Telegram offset。主动忽略的非法/未授权更新也会先把 offset 持久化。
- 消息入队并持久化 offset 后，机器人会尽力回复“任务已收到”。即使这条提示发送失败，也不会回滚任务或导致重复入队。
- 同一时间只有一个可取消的轮询器。遇到 `429` 会按 `retry_after` 等待，其他可恢复错误使用有限退避；遇到 `401`、凭据变化、机器人身份变化或已有 Webhook 时会停止并显示明确状态。
- 发出的纯文字会安全拆成最多 4096 个 UTF-16 单元的分段，不会切断代理对字符。

存储域名称是 `channel_telegram`，只保存机器人身份、绑定身份、offset、配对摘要或待确认账号，不保存 Bot Token、Webhook 地址和凭据指纹。

## 模型体验

### 已认证 Telegram 文本

#### 模型看到的内容

这个提供方不会直接向模型提供内容。电脑确认绑定后，它把来自 `getUpdates` 的标准化私聊文本和不透明传输身份交给已注册的 Channel 消费者；Bot 凭据、Telegram 资料字段、配对命令和 Bot API 元数据不会在本包变成模型上下文。

#### Token 影响

本包直接增加的 Token 为零。注册的消费者可以按自身规则把已接纳文本加入模型请求；配对、状态检查、接收提示和出站回复不会在本包消耗模型 Token。

#### KV Cache 影响

这个提供方不创建模型请求，也不改变已有可复用前缀。已接纳文本的缓存行为由选定的 Channel 消费者和 Agent 会话负责。

## 已知限制与后续工作

- 提供方只接受一个精确绑定的私聊身份发来的文本。群聊、媒体、编辑和 reaction 不会被接纳。
- Bot 已设置 Webhook 时无法启动长轮询，提供方也不会自动删除该 Webhook。
- Host 和网络必须保持可用，才能继续轮询与投递。激活期间提供方可能拉取并检查一批更新，但一旦发现积压，通道会保持停用，不执行、不确认、不推进 offset，也不清空这些更新。
