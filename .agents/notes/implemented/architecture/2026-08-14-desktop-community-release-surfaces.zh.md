# Agent Note: 桌面社区功能保持证据边界与发布门禁

Status: implemented

[English](2026-08-14-desktop-community-release-surfaces.md) | 中文

## 问题

社区桌面版需要的不只是为 Web 工作区增加一个窗口，还包括 Agent 可选择的图片与视频生成、社区插件发现、提供方优惠、原生版本与反馈控制，以及更新渠道。每个功能都会跨越信任或费用边界：媒体调用可能产生费用，话题标签不能证明仓库就是 Harness 插件，第三方安装会执行代码，公开免费方案不等于赞助关系，未签名下载也不能被描述为安全的自动更新。

公共仓库还继承了面向 DeepSeek 密钥、npm 发布族和自托管 Runner 设计的上游工作流。如果社区 Fork 原样运行这些流程，会产生虚假失败或具有误导性的发布路径。

## 决策

媒体生成作为可选的 Host/Client 包提供，并拆分图片与视频工具。提供方配置和凭据由 Host 管理；完成配置前工具保持关闭，默认执行策略会在付费调用前询问。生成文件使用专用附件或 Artifact 路径与媒体结果卡片，不会把 DeepSeek 下一轮请求不支持的图片块放入模型上下文。

插件市场采用展示来源的目录模型。它从 GitHub `dsh-plugin` 话题读取一页有界结果并缓存，展示来源与许可证事实，并且只验证用户选择的单个仓库。验证会把默认分支解析到具体提交，读取固定版本的 `package.json`，要求存在 `dsh.bundle.patch`，并确认固定版本的 Patch 目标存在，然后才把项目标为兼容。话题成员身份始终只代表未核验发现。GitHub、npm 和本地来源表单只提供风险预览；本版本不包含安装子进程，确认调用会以 `installation-disabled` 安全失败。

公开提供方优惠必须包含官方来源、资格条件、条款、申请链接和核验日期。界面会把它们与已核验合作伙伴目录分开展示，合作伙伴目录初始为空。任何公开方案都不会被称为赞助商，也不会承诺用户一定获得额度。

原生应用菜单集中提供 About 归属信息、已安装版本、手动检查更新、版本说明和反馈。更新器在开发环境和 Ad-hoc 包中保持离线，只有通过严格 Developer ID 验证后才会启用。它只跟随 GitHub Release，不跟随任意提交；版本文本会去除不安全格式并限制长度；自动下载与退出时自动安装均关闭；下载和重启前都会分别询问用户。

打包流程把桌面图标固定到上游 Web Favicon 的精确字节，并记录来源与输出哈希。本地打包命令始终使用 `--publish never`。Desktop Release 工作流要求 Apple 凭据，在 Apple Silicon Runner 上构建 Arm64，并在创建 GitHub Release 前验证版本、签名、Team ID、Gatekeeper 评估、App 公证票据、ATS、图标、更新 Feed 和产物名称。凭据缺失时安全失败，绝不会降级发布未签名产物。外层 DMG 公证仍是发布前提；把该容器发送到 Apple 公证服务还需要用户明确授权。

社区 Fork 使用独立的无密钥 Desktop CI 和双语 GitHub Pages 站点。上游 npm 发布、真实 API、Sandbox、Landlock 和默认分支自托管任务只允许在 `deepseek-ai/deepseek-harness` 运行，不会被重新解释为社区版发布证据。

## 曾考虑的替代方案

- **把每个话题结果都当成可安装插件。** 已否决，因为 GitHub 话题由仓库自行添加，当前结果中确实包含无关项目。
- **单击后直接安装。** 当前 Beta 已否决，因为 Git、Registry 和本地包可能在 Agent 沙箱之外执行安装脚本；发现与执行需要分别获得授权。
- **把提供方公开免费方案列为赞助商。** 已否决，因为公开方案不能证明商业关系，也不能保证某位用户具备资格。
- **在所有打包版本中启用更新。** 已否决，因为 Ad-hoc 构建不能建立可信替换所需的签名身份。
- **让 Electron Builder 在打包时直接发布。** 已否决，因为产物必须先完整生成并通过独立门禁，随后才能修改外部 Release。

## 后果

- Beta 可以提供实用的媒体、发现、优惠、版本和反馈功能，同时让代码执行与付费调用保持明确。
- 市场中的兼容标记只代表固定版本的 Bundle 形状已通过验证，不代表安全审计结果，也不授予安装权限。
- 已签名的 GitHub Release 可以支持应用内更新提示；本地未签名构建仍可用于验证，但不会成为分发产物。
- 源码与 Pages 可以独立公开；二进制分发仍需等待 Apple 签名、公证以及最终更新安装证据。
