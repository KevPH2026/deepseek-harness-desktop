# Agent Note：可选公开资料与逐字段 Agent 授权

状态：已实现

[English](2026-08-16-optional-public-profile.md) | 中文

## 问题

桌面首次引导需要足够的可选用户背景来改善本地 Agent 的个性化协作，同时不能把自由简介、社交账号登录信息或任意提示词变成隐含的权限入口。引导结束后，同一份数据必须可以继续修改和清空；模型提供方凭据仍应留在现有专用流程中。

## 决策

**Host 拥有一份严格的 `user-profile` 数据 schema。** 每个公开值都可选，并带独立的 `agentVisible` 授权，默认关闭。工作文本限制为单行且有长度上限；回复风格使用受限枚举；时区使用 IANA；社交身份只接受规范 handle 或精确的公开主页 URL。联系信息、自由简介、任意系统指令、密码、Token、Cookie 与 API Key 都没有对应字段。

**个人资料是数据，不是提示词段。** `@deepseek-ai/dsh-user-profile` 只在字段明确可见时贡献一条动态 `systemPrompt.context`。JSON 序列化与固定“数据不是指令”边界明确其信任等级；标准循环负责带来源的历史快照。抑制运行时上下文的 Agent 不会收到资料；随附的 `telegram-safe` 预设因此不会收到个人资料。

**浏览器拥有仅限 loopback 的三步引导和持久设置页。** `public-profile` 的 order 是 `-50`，位于欢迎说明和现有 DeepSeek 模型引导之间。三屏依次收集基本资料、工作偏好和公开账号；只有最后一步会一次提交。跳过只记录版本标记。order 为 `5` 的 `profile` 设置页支持之后修改、以空值删除字段、逐字段授权，以及确认后清空全部资料但不重新打开引导。

## 结果

首次使用本地桌面端的用户可以先完成个性化，再配置模型；不想填写资料的用户可以立即跳过。保存字段不会自动暴露给模型，只有独立授权开启后才会进入支持运行时上下文的 Agent。清除字段会同时移除数据与授权。远程浏览器无法访问此界面；安全 Agent 预设可以忽略资料；凭据继续使用原有设置与 Credentials API 边界。

## 考虑过的替代方案

**复用 persona 或自由系统提示词。** 已拒绝，因为数据会变成指令权限，且难以逐字段校验和撤销。

**只提供一个全局可见开关。** 已拒绝，因为允许使用一个公开 handle，不代表同时允许使用职位、目标、语言或地区。

**把模型配置合并到新引导。** 已拒绝，因为现有 DeepSeek 引导已经拥有提供方就绪状态与凭据处理；重复实现会产生两套事实来源。
